# Правила разработки проекта

## 1. Ограничение размера файлов и компонентов (Правило 200 строк)
* **Ни один файл с исходным кодом (`.py`) не должен превышать 200 строк.**
* Если файл приближается к 200 строкам или превышает их, он **обязан** быть разбит на логические модули согласно принципу единственной ответственности (Single Responsibility Principle).
* Модули UI не должны содержать тяжелую бизнес-логику — она выносится в сервисы или утилиты.
* Стили (CSS / QSS), крупные константы и шаблоны оформления выносятся в отдельные файлы (`styles.py`, `constants.py` и т.д.).

## 2. Архитектура и структура кода
* **Чёткое разделение слоёв:**
  - `core / domain`: парсинг, вычисление дельт, валидация ИНН (чистые функции, независимые от GUI).
  - `excel`: чтение через `openpyxl`, запись через COM/Win32, генерация Excel-отчётов.
  - `ui`: компоненты интерфейса PySide6, связывание событий, визуализация.
* **DRY (Don't Repeat Yourself):**
  - Никакого дублирования функций преобразования чисел или нормализации строк.
  - Общие утилиты выносятся в соответствующие общие модули.
* **Безопасность ресурсов (COM и файлы):**
  - Работа с Excel через COM должна осуществляться через безопасные контекстные менеджеры, гарантирующие закрытие рабочих книг и завершение процессов `EXCEL.EXE`.

## 3. Тестирование
* Вся доменная логика и функции преобразования должны сопровождаться модульными тестами в `tests/`.
